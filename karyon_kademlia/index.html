§Karyon kademlia

Kademlia DHT discovery for karyon_p2p. It keeps a routing table of known peers, fills it with lookups through bootstrap peers, checks entries with UDP liveness pings, and hands the node peers to dial.

§Install

$ cargo add karyon_p2p karyon_kademlia

§Example

use karyon_core::async_runtime::global_executor;
use karyon_kademlia::{KademliaConfig, KademliaDiscovery};
use karyon_p2p::{
    Config, Node,
    keypair::{KeyPair, KeyPairType},
};

async {
    let key_pair = KeyPair::generate(&KeyPairType::Ed25519);

    // Node settings: where to listen, slots, timeouts, ...
    let config = Config {
        listen_endpoints: vec!["tcp://0.0.0.0:8000".parse().unwrap()],
        ..Config::default()
    };

    // Kademlia settings: its own sockets and the seeds.
    let kconfig = KademliaConfig {
        discovery_endpoints: vec![
            "tcp://0.0.0.0:7000".parse().unwrap(),
            "udp://0.0.0.0:7000".parse().unwrap(),
        ],
        bootstrap_peers: vec!["tcp://seed.example.com:7000".parse().unwrap()],
        ..KademliaConfig::default()
    };

    // The closure gets the node's key pair, PeerID, config, monitor and
    // executor.
    let node = Node::with_discovery(
        &key_pair,
        config,
        |ctx| KademliaDiscovery::new(ctx, kconfig),
        global_executor(),
    );

    node.run().await.expect("Run the node");
    node.shutdown().await;
};

§Transport

With Config::transport set, lookups dial and listen through it too, and the node sends no raw UDP: the refresh service pings each entry over the lookup protocol instead, and the udp:// discovery endpoint is not used. Without a transport, refresh uses UDP, and pings over the lookup protocol only entries that have no UDP address.

§Advertised items

Node::advertise items go into the bloom filter sent to other peers, and filter which peers from the routing table the node dials: a peer must advertise every REQUIRED item and, if any PREFERRED item is set, at least one of them. Items with only ProtocolFlags::USER bits are advertised but do not affect peer selection.

§Monitor

Kademlia posts DiscoveryEvents to the node’s monitor (node.monitor().register::<DiscoveryEvent>()): LookupStarted, LookupFailed, LookupSucceeded (with the number of peers found), RefreshStarted, RefreshSucceeded (with the number of entries pinged), RefreshFailed and EntryEvicted.
